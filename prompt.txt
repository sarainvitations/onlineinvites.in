# Online Invites — Updated Codex Development Prompt

## Project objective

Build a production-quality, mobile-first digital invitation business website called **Online Invites**.

**Domain:** `onlineinvites.in`  
**Tagline:** Every Celebration Deserves a Beautiful Invitation.

The platform will offer beautiful, animated, customizable digital invitations for weddings, Nikah, Walima, engagements, Aqiqah, birthdays, anniversaries, Griha Pravesh, Puja, housewarming and other celebrations.

The business follows a **quotation-first model**, not direct checkout.

Customers browse invitation demos, submit their requirements, receive a personalized quotation, approve it, and pay upfront before development begins.

The first preview will be delivered within three working days after payment confirmation and receipt of complete requirements.

## 1. Technology stack

Use:

- React with TypeScript
- Vite
- Tailwind CSS
- Motion for React for animations
- React Router for navigation
- Lucide React for icons
- Cloudflare Pages for frontend hosting
- Cloudflare Pages Functions for backend APIs
- Cloudflare D1 for enquiry storage
- Cloudflare Turnstile for spam protection
- Cloudflare Email Routing for incoming business email forwarding
- Wrangler for local Cloudflare development and deployment

Do not use Netlify, Firebase, Supabase or a separate paid backend for the MVP.

Keep the application modular, accessible, SEO-friendly and easy to extend.

## 2. Design direction

Create a premium, contemporary invitation design studio website.

The website should feel elegant and trustworthy, not like a generic e-commerce template.

Use:

- Sophisticated typography

- Emerald, champagne gold and muted accent colors
- Subtle gradients
- Soft shadows
- Elegant cards
- Generous spacing

- Micro-interactions
- Responsive layouts

Avoid excessive animations, distracting effects and large JavaScript bundles.

Support reduced-motion accessibility preferences.

## 5. Backend architecture

Use Cloudflare Pages Functions.

Create an endpoint such as:

`POST /api/enquiries`

The endpoint must:

1. Validate incoming data server-side.
2. Enforce request-size and field-length limits.
3. Verify the Turnstile token server-side.
4. Normalize and sanitize user inputs appropriately.
5. Generate a unique enquiry ID.
6. Store the enquiry in Cloudflare D1.
7. Return a safe success response.
8. Handle failures without exposing sensitive implementation details.

Add appropriate rate limiting and basic duplicate-submission protection.

Never trust frontend validation alone.

Do not expose database credentials, API keys or other secrets in frontend code.

## 7. Email integration

Initially, the business owner will use a personal email inbox.

Support the future use of:

`contact@onlineinvites.in`

Cloudflare Email Routing may forward incoming business emails to the personal inbox.

Important: Email Routing is not a transactional outbound email service.

Implement an email-notification abstraction that supports a future transactional email provider.

Do not assume Cloudflare Email Routing can send enquiry notifications.

The application must work correctly even when no outbound email provider is configured.

Every enquiry must be stored successfully in D1 independently of email delivery.

For the MVP, provide a documented method for securely retrieving new enquiries until email notifications are configured.

Do not expose customer information through public endpoints.
